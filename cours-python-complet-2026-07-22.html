Fonctions & variables

guido's gorgeous lasagna · def, return, =

🏷️ Une variable = une étiquette sur une boîte ▶
🏷️ L'image : une variable, c'est une étiquette que tu colles sur une valeur pour la retrouver. Le signe = veut dire "colle cette étiquette sur cette valeur" (ce n'est PAS l'égalité des maths).
age = 43            # l'étiquette "age" pointe sur 43
age = "quarante-trois"  # tu peux la recoller ailleurs quand tu veux

Une constante, c'est une étiquette qu'on promet de ne jamais recoller. Convention : on l'écrit tout en majuscules → TAUX_TVA = 0.20.

🤔 Après x = 5 puis x = 9, que vaut x ?
9. La dernière étiquette collée gagne.
⚙️ Une fonction = une machine ▶
⚙️ L'image : une fonction, c'est une machine. Tu y mets des ingrédients (les paramètres), elle fait son travail, et elle te rend un résultat (le return).
def additionne(a, b):   # def = "je fabrique la machine", a et b = ingrédients
    return a + b        # return = "voilà le plat servi"

additionne(3, 4)          # -> 7  (on met 3 et 4, elle rend 7)
   3 ┐
     ├──►[ additionne ]──► 7
   4 ┘   (la machine)   (résultat)
⚠️ Piège : pas de return = la machine rend None Si tu oublies return, la fonction calcule peut-être un truc, mais elle ne te rend rien (None = "rien"). C'est l'erreur n°1 du débutant.
🎯 Où ça sert Tout Exercism, c'est ça : on te donne une machine vide (def ...: pass) et tu écris ce qu'elle doit faire + ce qu'elle doit return.
🤔 def f(x): x + 1 (sans return). Que rend f(10) ?
None. Elle calcule x + 1 mais ne le rend pas, faute de return.
💬 Commentaires & docstrings ▶

Un commentaire commence par # : Python l'ignore, c'est une note pour les humains. Une ligne = un # (pas de commentaire multi-lignes en Python).

Une docstring, c'est le petit texte entre """triple guillemets""" juste sous le def : elle explique ce que fait la machine. C'est ce que tu vois en haut de chaque exo Exercism.

def aire(cote):
    """Calcule l'aire d'un carré."""   # docstring
    return cote * cote

Les booléens (vrai / faux)

ghost gobble · True, False, and, or, not

💡 Un booléen = un interrupteur ▶
💡 L'image : un booléen n'a que deux positions, comme un interrupteur : allumé (True) ou éteint (False). Attention à la majuscule : True/False, jamais true.
porte_ouverte = True
alarme = False
🔀 Combiner : and, or, not ▶
  • and → vrai seulement si les DEUX sont vrais. (il faut la clé et le code)
  • or → vrai si AU MOINS UN est vrai. (le train ou le bus)
  • not → l'inverse. (not True → False)
True and False   # -> False (l'un des deux est éteint)
False or True    # -> True  (au moins un est allumé)
not False       # -> True  (on inverse)
🎯 Où ça sert Dans ghost-gobble : "Pac-Man peut manger le fantôme" = vrai seulement si pac-man a mangé la pastille and le fantôme est bleu.
🤔 (True and False) or not False vaut quoi ?
True. True and False → False ; not False → True ; False or True → True.

Les nombres

currency exchange · int, float, //, %

🔢 Deux familles : int et float ▶
🔢 L'image : un int = des billes entières (1, -10, 42), tu ne peux pas en avoir 3,5. Un float = un volume avec décimales (3.14, 0.0, -9.01), il a une virgule (un point en anglais).
🤔 7 et 7.0, même type ?
Non : 7 est un int, 7.0 est un float. Même valeur, familles différentes.
➗ Les deux divisions : / et // ▶

La division normale / rend toujours un float, même sur des entiers ronds :

6 / 2     # -> 3.0  (float ! pas 3)
7 / 4     # -> 1.75

La division entière // coupe et jette les décimales (elle "tronque") :

7 // 4    # -> 1   (1.75, on jette le ,75)
6 // 2    # -> 3
✅ Rappel making-the-grade C'est exactement le // que tu as utilisé pour (highest - 40) // 4 : tu voulais un pas entier pour tes tranches de notes, pas un 1.75 qui casse range().
🍰 Le reste : % (modulo) ▶
🍰 L'image : % te donne ce qui reste après avoir partagé. 7 bonbons pour 4 enfants → chacun 1, il reste 3.
7 % 4     # -> 3  (le reste)
10 % 2    # -> 0  (pile poil, donc 10 est pair)
🎯 Où ça sert Test pair/impair : n % 2 == 0 = "reste nul" = pair. Tu le reverras dans les boucles.
🤔 13 % 5 = ? et 13 // 5 = ?
13 % 5 → 3 (le reste). 13 // 5 → 2 (combien de fois 5 rentre).
🔄 Changer de famille : int() et float() ▶ 
int(3.9)    # -> 3   (coupe les décimales, ne s'arrondit PAS)
float(5)    # -> 5.0
⚠️ Piège int() tronque, il n'arrondit pas : int(3.9) donne 3, pas 4. Pour arrondir, c'est round(3.9) → 4.

Les comparaisons

black jack · > < == is in

⚖️ La balance : > < == ▶
⚖️ L'image : une comparaison, c'est une question à laquelle Python répond par oui (True) ou non (False).
SigneQuestion
> / <strictement plus grand / plus petit
>= / <=plus grand/petit ou égal
==est égal à ? (deux = !)
!=est différent de ?
⚠️ Le piège classique = (un seul) = "colle une étiquette". == (double) = "est-ce égal ?". Dans un if, c'est toujours ==.
✅ Rappel making-the-grade <= vs < t'a piégé : "au plus 40" (échec) c'est note <= 40, le 40 est inclus. Le "ou égal" compte.
🔗 Enchaîner : x < y < z ▶

Python autorise le langage des maths : 18 <= age < 65 se lit "âge entre 18 et 65". Pas besoin de and.

x, y, z = 2, 5, 10
x < y < z    # -> True   (2 < 5 ET 5 < 10)
👯 == vs is : même valeur ≠ même objet ▶
👯 L'image : deux vrais jumeaux ont la même apparence (==, même valeur) mais ce ne sont pas la même personne (is, même objet exact en mémoire).

En pratique de débutant : utilise == pour comparer des valeurs. Réserve is à un seul cas : x is None.

🔍 in : est-ce dedans ? ▶ 
"Bat" in "Super Batman"   # -> True  (sous-texte présent)
22 in [11, 22, 33]         # -> True  (élément présent)
🤔 Dans un if pour tester l'égalité, j'écris = ou == ?
== (double). Le simple = sert à assigner et fera une erreur dans un if.

Les strings (le texte)

little sister's vocab · index, slicing, +, .split(), .join()

📿 Un string = un collier de perles ▶
📿 L'image : un texte, c'est un collier où chaque perle est un caractère, rangé dans l'ordre. On l'écrit entre guillemets '...' ou "...".

Chaque perle a un numéro de place (index), depuis la gauche (0) ou la droite (-1) — exactement comme les tuples :

m  o  t
[0][1][2]      <- depuis la gauche
[-3][-2][-1]   <- depuis la droite
mot = "chat"
mot[0]    # -> "c"
mot[-1]   # -> "t"
✅ Rappel tisbury Ton convert_coordinate faisait coordinate[0], coordinate[1] pour séparer "2" et "A". Même principe.
✂️ Couper un bout : le slicing [début:fin] ▶
✂️ L'image : le slicing coupe une tranche du collier. [2:5] = "de la perle 2 jusqu'AVANT la 5".
mot = "exercism"
mot[0:4]   # -> "exer"  (0,1,2,3 — le 4 est exclu)
mot[:3]    # -> "exe"   (début omis = depuis 0)
mot[3:]    # -> "rcism" (fin omise = jusqu'au bout)
⚠️ La règle en or La borne de fin est toujours exclue. [0:4] te donne 4 perles (0 à 3), pas 5. C'est LE même piège que range().
🧩 Coller & découper : +, .split(), .join() ▶

Coller deux textes avec + :

"bon" + "jour"   # -> "bonjour"

Découper un texte en liste de mots avec .split() :

"le chat dort".split()      # -> ["le", "chat", "dort"]
"a,b,c".split(",")         # -> ["a", "b", "c"]

Ré-assembler une liste en texte avec .join() (l'inverse de split). Attention : le séparateur est devant le .join :

" ".join(["le", "chat"])   # -> "le chat"
"-".join(["06", "12", "34"]) # -> "06-12-34"
🤔 "2026-07-22".split("-") rend quoi ?
["2026", "07", "22"] — une liste de 3 morceaux, coupés sur le tiret.

Les méthodes de texte

little sister's essay · .title(), .strip(), .replace(), .endswith()

🧰 Une méthode = un outil collé au texte ▶
🧰 L'image : une fonction est une machine à part (round(x)). Une méthode est un outil attaché à l'objet, avec un point : "texte".title(). Le point = "applique ton outil sur moi".
⚠️ Immuable Le texte de départ ne change JAMAIS. Une méthode rend une copie modifiée. "abc".upper() te donne "ABC" mais "abc" reste "abc". Il faut récupérer le résultat dans une variable.
🔧 Les 4 outils de l'exo ▶
OutilCe qu'il faitExemple
.title()Majuscule à chaque mot"le chat".title() → "Le Chat"
.strip()Enlève les espaces au bord" hi ".strip() → "hi"
.replace(a, b)Remplace a par b partout"aaa".replace("a","b") → "bbb"
.endswith(x)Se termine par x ? (vrai/faux)"chat.".endswith(".") → True
⚠️ La ponctuation compte .endswith("chat") sur "le chat." → False, à cause du point final. Le texte, c'est au caractère près.
🤔 Après nom = " julien " et nom.strip(), que vaut nom ?
Toujours " julien " ! .strip() rend une copie mais ne modifie pas l'original. Il fallait écrire nom = nom.strip().

Les listes

card games · [ ], index, slicing, len(), sum()

🛒 Une liste = un chariot de courses ▶
🛒 L'image : une liste, c'est ta trousse ou ton chariot : des éléments dans l'ordre, entre crochets [ ], et surtout tu peux ajouter / enlever / changer (contrairement au tuple scellé).
courses = ["pain", "lait", "œufs"]
courses[0]    # -> "pain"  (index comme partout : 0 à gauche, -1 à droite)
courses[-1]   # -> "œufs"
🧠 À retenir Liste [ ] = modifiable. Tuple ( ) = scellé. String "..." = scellé. Même notation d'index pour les trois.
📏 Mesurer & additionner : len(), sum() ▶ 
len(["a", "b", "c"])   # -> 3   (combien d'éléments)
sum([10, 20, 30])   # -> 60  (somme, si ce sont des nombres)
⚠️ Piège d'index Une liste de 3 éléments a les index 0, 1, 2. Le dernier index = len - 1, pas len. Demander liste[3] ici → IndexError.
✂️ Slicing & collage : [a:b], +, * ▶

Comme sur le texte : on coupe des tranches, la fin est exclue.

nums = [10, 20, 30, 40, 50]
nums[1:3]   # -> [20, 30]
nums[::2]   # -> [10, 30, 50]  (un sur deux)
[1, 2] + [3]  # -> [1, 2, 3]  (coller)
🤔 len(["x", "y"]) vaut 2. Quel est l'index du dernier élément ?
1 (et non 2). Les index vont de 0 à len - 1.

Les méthodes de liste

chaitana's coaster · .append(), .pop(), .sort()…

✋ Ces outils modifient le chariot SUR PLACE ▶
⚠️ La grande différence avec le texte Les méthodes de liste changent la liste d'origine (elle est modifiable). Pas besoin de ma_liste = ma_liste.append(...) — d'ailleurs ça casse tout (voir piège plus bas).
➕ Ajouter : .append(), .insert(), .extend() ▶ 
nums = [1, 2, 3]
nums.append(9)      # -> [1, 2, 3, 9]   ajoute 1 élément à la fin
nums.insert(0, -2)  # -> [-2, 1, 2, 3, 9]  ajoute à un index précis
nums.extend([7, 8]) # -> [..., 7, 8]  ajoute PLUSIEURS éléments
⚠️ append vs extend .append([7,8]) ajoute la liste entière comme UN seul élément → [..., [7,8]]. .extend([7,8]) ajoute 7 puis 8 séparément. C'est la cause de tes "crochets en trop".
✅ Rappel making-the-grade Tu bâtissais tes résultats avec resultat.append(...), un élément à la fois. Et le bug de perfect_score ([['Joci',100]] au lieu de ['Joci',100]) venait exactement d'un niveau de crochets en trop.
➖ Enlever : .remove(), .pop(), .clear() ▶ 
nums = [1, 2, 3]
nums.remove(2)   # enlève la VALEUR 2 -> [1, 3]
nums.pop(0)      # enlève par INDEX et te rend l'élément -> renvoie 1
nums.clear()     # vide tout -> []

.remove() vise une valeur, .pop() vise une place (index) et te rend ce qu'il retire.

🔀 Ranger : .sort(), .reverse(), .count() ▶ 
noms = ["Tony", "Bruce", "Thor"]
noms.sort()              # range dans l'ordre -> ['Bruce','Thor','Tony']
noms.sort(reverse=True)  # ordre inverse
[1,1,2,1].count(1)       # -> 3   combien de fois 1 apparaît
⚠️ Le piège qui déroute tout le monde .sort() range sur place et rend None. Donc ma_liste = ma_liste.sort() détruit ta liste (elle devient None) ! Écris juste ma_liste.sort(). Pour garder l'original, utilise la fonction sorted(ma_liste) qui, elle, rend une copie triée.
🤔 scores = [3, 1, 2] puis scores = scores.sort(). Que vaut scores ?
None 😱. .sort() trie sur place et ne rend rien. Il fallait juste scores.sort() tout court.

if / elif / else

meltdown mitigation · prendre des décisions

🚦 Un if = un aiguillage ▶
🚦 L'image : if, c'est un aiguillage de train. Selon que la condition est vraie ou fausse, le train part sur une voie ou une autre.
if temperature > 100:
    print("trop chaud")
else:
    print("ça va")

La condition doit répondre vrai ou faux (souvent une comparaison du chapitre 4).

🪜 elif : plusieurs voies ▶
🪜 L'image : elif = "sinon, essaie plutôt ça". Python teste les conditions de haut en bas et s'arrête à la première vraie. Le else attrape tout le reste.
if note >= 85:
    lettre = "A"
elif note >= 70:
    lettre = "B"
else:
    lettre = "échec"
⚠️ L'ordre compte Comme Python s'arrête à la première condition vraie, va du plus strict au plus large. Si tu mets note >= 70 en premier, un 90 tomberait dedans et n'atteindrait jamais le "A".
🤔 Avec le code ci-dessus, quelle lettre pour note = 90 ?
"A". 90 ≥ 85 est vrai dès la 1re ligne, Python s'arrête là.

Les boucles

making the grade · for, while, range(), enumerate()

🎞️ for = passer sur chaque élément ▶
🎞️ L'image : for, c'est un tapis roulant : chaque élément passe devant toi, un par un, et tu fais quelque chose avec.
for note in [12, 8, 15]:
    print(note)     # affiche 12, puis 8, puis 15
✅ Ton squelette making-the-grade accumulateur vide → for → filtre avec if → .append() → return APRÈS la boucle. Ce moule marche pour 90% des exos.
🔢 range() = un compteur ▶ 
range(4)        # 0, 1, 2, 3
range(1, 7)     # 1, 2, 3, 4, 5, 6
range(3, 15, 2) # 3, 5, 7, 9, 11, 13  (pas de 2)
⚠️ La borne de fin est exclue range(1, 7) s'arrête avant 7. Même règle que le slicing. C'est ce qui t'a créé une 5e tranche en trop dans letter_grades — tu as basculé sur range(4) + formule pour avoir pile 4 valeurs.
🔗 enumerate() = numéro + valeur ▶

Quand tu as besoin de la place ET de la valeur en même temps :

for index, mot in enumerate(["a", "b"]):
    print(index, mot)   # 0 a  /  1 b
✅ Rappel Tu as réécrit student_ranking avec enumerate pour avoir le rang (index) et le nom ensemble — c'est aussi ce que Pylint te réclamait (C0200).
🔁 while, break, continue ▶

while = "répète tant que c'est vrai". break = "sors de la boucle maintenant". continue = "saute au tour suivant".

for n in range(10):
    if n == 5:
        break       # stoppe tout à 5
    if n % 2 == 0:
        continue    # saute les pairs
    print(n)        # 1, 3
🤔 Combien de nombres produit range(2, 8) ?
6 : 2, 3, 4, 5, 6, 7. Le 8 est exclu.

🥚 L'image : une boîte d'œufs scellée : une fois fermée, tu ne peux ni ajouter, ni enlever, ni remplacer. L'ordre est figé. On le reconnaît à ses parenthèses ( ). C'est le contraire de la liste (la trousse, modifiable).

Les dictionnaires

inventory management · { }, clé/valeur, .items()

🗄️ Un dict = un meuble à tiroirs étiquetés ▶
🗄️ L'image : un dictionnaire, c'est un meuble à tiroirs étiquetés. Chaque tiroir a une étiquette (la clé) et un contenu (la valeur). Tu ranges et retrouves par le nom de l'étiquette, pas par un numéro de place.

Le problème que ça règle : avec une liste [7, 11, 2], le 7 c'est le stock de quoi ? Mystère. Le dict colle une étiquette sur chaque nombre :

stock = {"coal": 7, "wood": 11, "diamond": 2}
             ▲étiquette  ▲contenu
               (clé)     (valeur)
🧠 Les 3 boîtes, au complet Liste [ ] = rangé par numéro. Tuple ( ) = pareil mais scellé. Dict { } = rangé par étiquette. Le : entre clé et valeur = la marque du dict.
🔑 Lire, créer, changer un tiroir ▶

On écrit un dict "à la main" (un dict littéral — juste du jargon pour "écrit dans le code avec des accolades") :

stock = {"coal": 7, "wood": 11}

stock["coal"]        # -> 7    LIRE le tiroir "coal"
stock["gold"] = 5      # CRÉER le tiroir "gold" à 5
stock["coal"] = 99     # CHANGER le contenu de "coal"
⚠️ Piège : lire un tiroir qui n'existe pas stock["argent"] quand le tiroir n'existe pas → KeyError, ça plante. Pour tester avant, utilise "argent" in stock (rend True/False).
🤔 Avec stock = {"pomme": 4}, que fait stock["kiwi"] = 7 ?
Ça crée un nouveau tiroir "kiwi" avec la valeur 7 → {"pomme": 4, "kiwi": 7}. Écrire dans un tiroir inexistant le crée (contrairement à la lecture, qui plante).
🔢 Le pattern "compter" (ta fonction 1) ▶
🎯 L'usage star du dict : compter des choses. Tu passes sur une liste, et pour chaque élément tu montes son compteur d'un cran.
inventaire = {}                       # meuble vide
for article in items:
    if article in inventaire:          # tiroir déjà là ?
        inventaire[article] += 1      # +1
    else:
        inventaire[article] = 1       # sinon on le crée à 1
return inventaire
⚠️ Le piège que tu as repéré tout seul La 1re fois qu'on voit un article, son tiroir n'existe PAS encore. Faire directement +1 dessus → KeyError. D'où le if / else : on crée à 1, ou on incrémente.
✅ Dans ton exo C'est exactement create_inventory. Et add_items, c'était le même corps sans le inventaire = {} (le meuble arrivait déjà rempli).
🚪 Vérifier & retirer : in, .pop() ▶ 
"coal" in stock      # -> True/False   le tiroir existe ?
stock.pop("coal")     # retire le tiroir ENTIER (clé + valeur)

Nuance avec les listes : sur une liste, .pop(2) visait un index. Sur un dict, .pop("coal") vise une clé.

✅ Dans ton exo remove_item : if item in inventory: inventory.pop(item). Le if évite le KeyError si l'article n'est pas là.
🔁 Parcourir : clés seules vs .items() ▶
⚠️ Le piège de la boucle sur un dict Un for classique sur un dict ne te donne QUE les étiquettes (les clés), jamais le contenu :
for x in stock:
    print(x)     # affiche coal, wood... PAS 7, 11

Pour avoir l'étiquette ET le contenu ensemble, il faut .items() :

for cle, valeur in stock.items():
    print(cle, valeur)   # coal 7  /  wood 11
✅ Dans ton exo list_inventory : for article, quantite in inventory.items() pour construire la liste de tuples (article, quantite), en gardant seulement les quantités > 0.
🤔 Pour parcourir un dict et récupérer le nom ET la quantité, j'utilise quoi ?
.items() → for cle, valeur in stock.items(). Un for tout simple ne donnerait que les clés.

Dictionnaires — le niveau au-dessus

mecha munch · fromkeys, tri, déballage, dicts imbriqués

🏭 dict.fromkeys() : fabriquer un dict d'un coup ▶
🏭 L'image : une machine à étiqueteuse. Tu lui donnes une liste de noms et une valeur unique, elle te sort tout le meuble d'un coup, tous les tiroirs remplis pareil.
dict.fromkeys(["a", "b", "c"], 1)
# -> {"a": 1, "b": 1, "c": 1}
⚠️ Le piège des crochets (que tu as vécu) Si ta liste est déjà dans une variable notes, tu passes notes nu : dict.fromkeys(notes, 1). Écrire [notes] emballe toute la liste comme UNE seule clé. Règle : on met des crochets seulement quand on crée une liste, pas quand on en a déjà une.
✅ Dans ton exo read_notes tient en une ligne : return dict.fromkeys(notes, 1).
📦 Le déballage (unpacking) dans un for ▶
📦 L'image : chaque tour de boucle te tend un paquet (un tuple à 2 cases). Mettre deux noms à gauche du in ouvre le paquet et distribue les cases automatiquement.
# version longue
for paquet in data:
    nom = paquet[0]
    valeur = paquet[1]

# version courte (déballage) — exactement pareil
for nom, valeur in data:
    ...
⚠️ Un tour = UN paquet Dans for a, b in [(1, 2), (3, 4)], au 1er tour a=1, b=2 (le paquet entier), PAS a=1, b=3. On avance paquet par paquet, jamais case par case entre paquets.
✅ Dans ton exo for nom, ingredient in recipe_updates et for article, quantite in cart.items() — c'est le même déballage. .items() te sert justement des paquets (clé, valeur).
🤔 for x, y in [("a", 1), ("b", 2)] — au 2e tour, x et y valent ?
x = "b", y = 2 (le 2e paquet, déballé).
🔤 Trier un dict : dict(sorted(d.items())) ▶

Un dict n'a pas de bouton "trier". On passe par 3 poupées russes, lues de l'intérieur vers l'extérieur :

d.items()      →  liste de tuples (clé, valeur)   [désordonnée]
sorted( ... )  →  même liste triée A→Z sur la clé
dict( ... )    →  on reconstruit un dict trié
return dict(sorted(cart.items()))               # A→Z
return dict(sorted(cart.items(), reverse=True))  # Z→A
⚠️ Où va reverse=True ? Dans sorted(...) (c'est lui qui trie), jamais dans dict(...).
✅ Dans ton exo sort_entries (A→Z) et send_to_store (Z→A avec reverse=True).
🪆 Dicts imbriqués & le double crochet ▶
🪆 L'image : un tiroir peut contenir un autre meuble (dict de dict) ou une liste (dict de liste). Pour aller au fond, on enchaîne les crochets, de gauche à droite.
stock = {"Milk": [4, "Aisle 2", True]}

stock["Milk"]        # -> [4, "Aisle 2", True]  (la liste entière)
stock["Milk"][0]     # -> 4  (case 0 de cette liste)
stock[ "Milk" ][ 0 ]
      ▲          ▲
   1er crochet   2e crochet
   "va au        "prends la case 0
    tiroir Milk"  de la liste trouvée"

Et pour modifier une case en profondeur, même chose à gauche du = :

stock["Milk"][0] = 2              # remplace le stock par 2
stock["Milk"][0] = "Out of Stock" # ou par un texte
✅ Dans ton exo update_store_inventory : store_inventory[article][0] pour lire ET réécrire le stock au fond de la liste.
🤔 Avec d = {"x": [9, "A", False]}, que vaut d["x"][1] ?
"A" — le tiroir "x" donne la liste [9, "A", False], puis la case 1 de cette liste.

Emballage & déballage — * et **

locomotive engineer · le double rôle de l'étoile

⭐ La règle d'or : le double rôle de l'étoile ▶
⭐ L'idée : la même étoile * fait deux choses opposées selon où elle est. C'est LE piège de tout cet exo.
OùRôle
dans les paramètres def f(*x)EMBALLE — attrape tout dans un sac
partout ailleurs f(*liste)DÉBALLE — ressort les éléments un par un

Et le nombre d'étoiles indique le type de sac :

SigneConcerneRange dans
*listes / tuples (positionnels)un tuple
**dicts (arguments nommés)un dict
🎒 *args : le sac à arguments ▶
🎒 L'image : tu ne sais pas combien d'arguments on va te donner. *args dans les paramètres = un sac qui les attrape TOUS, dans un tuple.
def f(*trucs):
    print(trucs)

f(1, 2, 3)     # trucs vaut (1, 2, 3)
f()            # trucs vaut ()
✅ Dans ton exo get_list_of_wagons(*wagons) puis return list(wagons). Sans l'étoile, la fonction n'accepte qu'UN argument → l'erreur "takes 1 positional argument but 5 were given".
🤔 def f(*x), puis f("a", "b") — que vaut x ?
("a", "b") — un tuple contenant les deux arguments.
🗂️ **kwargs : le sac à arguments nommés ▶
🗂️ L'image : pareil, mais pour les arguments nommés clé=valeur. **kwargs les emballe dans un dict.
def f(**kwargs):
    print(kwargs)

f(a=1, b=2)    # kwargs vaut {"a": 1, "b": 2}
✅ Dans ton exo add_missing_stops(route, **kwargs) : les stop_1="..." sont emballés dans un dict, puis list(kwargs.values()) en sort les villes dans l'ordre.
✂️ Déballer avec * : couper une liste ▶

À gauche d'un =, * ramasse "tout le reste" dans une liste :

premier, *reste = [10, 20, 30, 40]
# premier = 10
# reste   = [20, 30, 40]

x, *milieu, y = [1, 2, 3, 4, 5]
# x = 1, y = 5, milieu = [2, 3, 4]
✅ Dans ton exo premier, second, loco, *rest = each_wagons_id — une ligne pour découper la liste, au lieu de plein de [0], [1]… Puis on recolle avec +.
🤔 a, *b = [1, 2, 3] — que valent a et b ?
a = 1, b = [2, 3]. L'étoile ramasse le reste dans une liste (même s'il n'y a qu'un élément).
🔗 Fusionner & transposer : {**a, **b} et zip(*grille) ▶

Fusionner deux dicts — ** vide chaque dict dans un nouveau :

{**{"x": 1}, **{"y": 2}}
# -> {"x": 1, "y": 2}

Déballer dans un appel — * sert les éléments séparément à une fonction :

grille = [ligne1, ligne2, ligne3]
zip(grille)    # ❌ zip reçoit 1 argument (la grille entière)
zip(*grille)   # ✅ zip reçoit ligne1, ligne2, ligne3 séparément

zip regroupe par position (le 1er de chaque ligne ensemble…) = une transposition (lignes ↔ colonnes).

✅ Dans ton exo fix_wagon_depot : for rangee in zip(*wagons_rows) transpose la grille ; list(rangee) reconvertit chaque rangée (zip rend des tuples).

Les sets (ensembles)

cater waiter · & | - .issubset()

🎯 Un set = la boîte anti-doublons ▶
🎯 L'image : un sac où chaque objet ne peut être présent qu'une seule fois. Tu y jettes deux "tofu" → il n'en reste qu'un. C'est la 4e boîte, en accolades { } avec juste des valeurs (pas de :, sinon c'est un dict).
{"pomme", "kiwi", "pomme"}
# -> {"pomme", "kiwi"}   les doublons disparaissent

set(["a", "b", "a"])   # -> {"a", "b"}  nettoie une liste

Ses 3 règles : pas de doublons, pas d'ordre (donc pas d'index set[0]), et le set vide s'écrit set().

⚠️ Le piège du set vide {} est le dict vide, pas le set vide. Pour un set vide c'est set(). (Retenu en fonction 5 : l'accumulateur resultat = set().)
🤔 Que vaut set(["x", "y", "x", "x"]) ?
{"x", "y"} — chaque élément une seule fois, l'ordre n'est pas garanti.
🔗 Les 3 opérateurs : & | - ▶

Trois façons de croiser deux sets (façon diagrammes de Venn) :

SigneNomDonne
&intersectionce qui est dans les DEUX
|uniontout regrouper (sans doublon)
-différencece qui est dans A mais PAS dans B
{"a", "b", "c"} & {"b", "c", "d"}   # -> {"b", "c"}
{"a", "b"} | {"b", "c"}          # -> {"a", "b", "c"}
{"a", "b", "c"} - {"b", "c"}      # -> {"a"}
✅ Dans ton exo & pour détecter l'alcool (check_drinks) et les allergènes (tag_special) ; | pour la liste maîtresse (compile_ingredients) ; - pour retirer les amuse-bouches (separate_appetizers) et isoler les singletons (union puis différence).
🤔 Quel opérateur pour "les ingrédients communs à deux plats" ?
& (intersection) — ce qui est présent dans les deux sets.
🎒 .issubset() : tout rentre-t-il dedans ? ▶
🎒 L'image : "est-ce que mon petit sac rentre entièrement dans le grand sac ?" — vrai seulement si tous mes éléments sont dans l'autre.
{"tofu", "sel"}.issubset({"tofu", "sel", "riz"})
# -> True
{"tofu", "bacon"}.issubset({"tofu", "sel"})
# -> False   (bacon manque)
✅ Dans ton exo categorize_dish : un plat est VEGAN si dish_ingredients.issubset(VEGAN). On teste chaque catégorie dans une boucle et on renvoie la première qui contient tout le plat.
⚠️ Piège Pylint R1710 — une boucle qui return a besoin d'un return final Si ton seul return est dans le if de la boucle, et que la boucle se termine sans rien trouver, la fonction renvoie None en douce. Un chemin rend une valeur, l'autre None → Pylint lève R1710 (inconsistent-return-statements). Fix : un return après la boucle (aligné avec le for) pour que TOUS les chemins renvoient le même genre. 
for nom, sac in categories.items():
    if dish_ingredients.issubset(sac):
        return f"{dish_name}: {nom}"
return ""   # filet de sécurité — jamais atteint, mais rend Pylint content
❄️ Un set non-vide = "vrai" ▶

Comme les listes, un set vide compte comme "faux" dans un if, un set non-vide comme "vrai". Pas besoin de comparer à set() :

alcool = set(ingredients) & ALCOHOLS
if alcool:              # vrai s'il y a au moins un alcool
    return "... Cocktail"
✅ Dans ton exo C'est le cœur de check_drinks : si l'intersection avec les alcools n'est pas vide → Cocktail.

Les classes (POO)

ellen's alien game · class __init__ self · attribut de classe vs instance

🧇 Une classe = un moule à gaufres ▶
🧇 L'image : jusqu'ici tu écrivais des fonctions posées à plat. Une classe, c'est un moule : le plan, qui ne se mange pas. Chaque objet que tu fabriques avec le moule est une instance (une gaufre). Toutes ont la même forme, mais chacune est indépendante — tu en manges une sans toucher les autres.
class Alien:          # le moule
    def __init__(self, x, y):   # la "chaîne de montage" (constructeur)
        self.x_coordinate = x      # une gaufre reçoit ses garnitures

alien = Alien(2, 0)     # on sort une gaufre du moule = instancier

self = "cette gaufre-ci", l'objet en cours. self.health = 3 veut dire "range 3 dans le tiroir health de cet objet précis".

🤔 Différence entre la classe Alien et un objet Alien(2, 0) ?
La classe est le moule (le plan, écrit une fois). Alien(2, 0) fabrique une instance concrète à partir du moule. Un moule → autant d'objets qu'on veut.
🏗️ __init__ : le constructeur, lancé à chaque naissance ▶
🏗️ L'image : __init__ ("dunder init", pour double underscore) est la chaîne de garnissage : Python la lance tout seul à chaque Alien(...). Son 1er paramètre est toujours self (la gaufre en cours) — mais tu ne le passes jamais, Python s'en charge.
def __init__(self, x_coordinate, y_coordinate):
    self.x_coordinate = x_coordinate   # passé par l'appelant → varie
    self.y_coordinate = y_coordinate
    self.health = 3                    # en dur → pareil pour tous
⚠️ Paramètre ou valeur en dur ? x/y changent d'un alien à l'autre → paramètres (Alien(2, 0)). La santé démarre toujours à 3 → écrite en dur, pas de paramètre health. Règle : on ne demande à l'appelant que ce qui varie.
✅ Dans ton exo Alien(2, 0) → .x_coordinate = 2, .y_coordinate = 0, .health = 3.
⚙️ Les méthodes : des fonctions attachées à l'objet ▶
⚙️ L'image : une méthode est une fonction dans la classe, avec self en 1er paramètre. C'est un bouton d'action que l'objet sait actionner sur lui-même. On l'appelle avec un point : alien.hit().
def hit(self):
    self.health = self.health - 1    # lit le tiroir, enlève 1, le repose

def is_alive(self):
    return self.health > 0         # une comparaison EST déjà un booléen
⚠️ Le point, pas le tiret bas self.health (point = "le tiroir health de l'objet"). self_health = un mot collé qui n'existe pas → NameError. Idem : sans self., Python ne sait pas d'où lire la valeur.
✅ Dans ton exo hit (−1 vie), is_alive (santé > 0), teleport (remplace les coords). Toutes prennent self, certaines des paramètres en plus comme __init__.
🤔 Pourquoi is_alive ne s'écrit-il pas if self.health > 0: return True else: return False ?
self.health > 0 vaut déjà True ou False. Le if/else est redondant (et Pylint le signale). On renvoie directement la comparaison.
🔢 Attribut de CLASSE vs attribut d'INSTANCE ▶
🔢 L'image : le compteur mécanique collé sur le moule. Il n'appartient à aucune gaufre — il appartient au moule, et fait +1 à chaque gaufre produite. Toutes les gaufres regardent le même cadran.
TypeOù / commentPortée
attribut de classetotal_aliens_created = 0, dans le corps de la classe, sans selfpartagé par tous
attribut d'instanceself.health = 3, dans __init__propre à chaque objet
class Alien:
    total_aliens_created = 0              # (A) le compteur DU MOULE (sans self)

    def __init__(self, x, y):
        self.health = 3
        Alien.total_aliens_created += 1  # (B) +1 à chaque naissance (vise Alien., pas self.)
⚠️ Deux règles neuves d'un coup (1) le corps d'une classe accepte des variables posées directement, pas que des def. (2) Pour incrémenter le compteur partagé on vise Alien. (le moule), pas self. (sinon chaque gaufre se crée un compteur privé). Et on lit l'attribut sans parenthèses : alien.total_aliens_created, pas () — c'est un nombre, pas une action.
✅ Dans ton exo Après avoir créé 2 aliens, a1.total_aliens_created vaut 2 (pas 1) : il lit le compteur du moule, partagé. Alors que a1.health ne bouge pas quand a2 est touché — santé propre à chacun.
🤔 self.total = 0 ou total = 0 pour un compteur partagé par tous les objets ?
total = 0 posé dans le corps de la classe (attribut de classe). self.total créerait une copie privée par objet — pas partagée.
🚪 pass : le bouche-trou d'un corps vide ▶
🚪 L'image : une pièce dont tu as posé la porte mais laissé l'intérieur vide. Python exige au moins une instruction après un : — un bloc vide plante. pass remplit le trou sans rien exécuter.
def collision_detection(self, other):
    pass   # "corps présent, mais volontairement vide" — algo à venir
✅ Dans ton exo Ellen veut que collision_detection existe comme rappel, sans planter à l'appel. pass réserve la place.
🏭 Une fonction autonome qui fabrique des objets ▶

La tâche 7 sort de la classe : une fonction normale (non indentée dans Alien) qui reçoit une liste de positions et renvoie une liste d'objets Alien. Le pattern liste que tu connais : accumulateur vide → boucle → .append().

def new_aliens_collection(positions):
    resultat = []
    for position in positions:               # chaque position = tuple (x, y)
        resultat.append(Alien(position[0], position[1]))
    return resultat
✅ Dans ton exo position[0] et position[1] découpent le tuple pour passer x et y séparément au constructeur.
🤔 Pourquoi Alien(position[0], position[1]) et pas Alien(position) ?
__init__ attend deux arguments (x et y). position est un seul tuple ; il faut l'éclater avec [0] et [1].

Les générateurs

plane tickets · yield next() · lazy, une valeur à la fois

🍬 Un générateur = la machine à bonbons ▶
🍬 L'image : un distributeur à manivelle. Tu tournes une fois → un bonbon tombe, puis la machine attend. Elle ne vide pas tout son stock d'un coup, et elle se souvient du dernier sorti. Un générateur produit ses valeurs une par une, à la demande — au lieu de tout calculer et stocker d'avance. C'est paresseux (lazy) et économe en mémoire.
return (fonction normale)yield (générateur)
Gestevide tout le sac et partdonne un truc, garde le sac
Aprèsla fonction est finieelle se met en pause, prête à reprendre
Mémoirestocke toute la listene garde qu'une valeur
def compte():
    yield "un"      # pause ici, rend "un"
    yield "deux"    # au next() suivant, REPREND ici, rend "deux"

g = compte()     # on reçoit la MACHINE (aucune valeur encore)
next(g)          # "un"  -> tourne la manivelle
next(g)          # "deux"
⚠️ Le déclencheur Dès qu'une fonction contient un seul yield, elle devient un générateur : l'appeler ne lance rien, ça te rend la machine. Les valeurs sortent avec next() ou une boucle for. Et list(gen) tourne la manivelle jusqu'au bout pour tout voir d'un coup.
🤔 Avec compte() ci-dessus, un seul next() rend combien de valeurs ?
Une ("un"). La machine garde le reste pour les prochains tours de manivelle.
🔁 yield dans une boucle ▶
🔁 L'image : plutôt qu'écrire yield 100 fois, on met un seul yield dans une boucle. Règle : 1 tour de boucle = 1 valeur distribuée.
def donne_nombres():
    for i in range(3):    # 3 tours -> 3 valeurs
        yield i
✅ Dans ton exo range(number) → la machine distribue exactement number valeurs. C'est la base des 4 tâches (générer number lettres, number sièges…).
🕐 % et // : l'horloge et la rangée ▶

Deux opérateurs (déjà vus dans currency-exchange) font le gros du boulot des sièges :

i % 4 — le modulo, "l'horloge" 🕐. Le reste de la division par 4 rabat toujours entre 0 et 3 : après 3, on revient à 0. Parfait pour faire tourner A, B, C, D en boucle sans jamais dépasser l'index 3.

# "ABCD"[i % 4]  ->  A,B,C,D,A,B,C,D...
i = 4  ->  4 % 4 = 0  ->  "A"   # on repart !
i = 7  ->  7 % 4 = 3  ->  "D"

i // 4 — la division entière, la "rangée". Elle garde le quotient (jette le reste) : combien de rangées complètes de 4 sont passées. + 1 car les rangées démarrent à 1.

row = i // 4 + 1
# i=0..3 -> 1 | i=4..7 -> 2 | i=8..11 -> 3
⚠️ Sauter la rangée 13 Conda ne numérote pas la rangée 13. Il faut décaler tout à partir de 13, pas seulement elle : if row >= 13: row += 1. Avec == 13 tu obtiendrais deux rangées 14 (la 13 décalée + la 14 d'origine).
🤔 Pourquoi row >= 13 et pas row == 13 ?
Une fois la 13 supprimée, toutes les rangées suivantes glissent de +1. == 13 ne corrigerait que la 13 et créerait un doublon de 14.
🎫 Utiliser un générateur : next() pour remplir un dico ▶

Une fonction normale (sans yield) peut utiliser un générateur. Ici : distribuer un siège à chaque passager avec next() et noter ça dans un dico.

def assign_seats(passengers):
    seats = generate_seats(len(passengers))   # machine de la bonne taille
    resultat = {}
    for passager in passengers:
        resultat[passager] = next(seats)      # tourne la manivelle -> siège suivant
    return resultat
✅ Dans ton exo next(seats) tire le siège suivant à chaque passager ; resultat[passager] = ... remplit le dico, exactement comme dans inventory-management.
0️⃣ Compléter un texte : "0" * n ▶
0️⃣ L'image : pour un code de 12 caractères pile, on colle le début (siège + vol) puis on bourre de zéros ce qui manque. * entre un texte et un nombre répète le texte.
"0" * 4    # -> "0000"

code = seat + flight_id               # "17D" + "CO1234" = "17DCO1234" (9 car.)
code + "0" * (12 - len(code))     # + "000" -> "17DCO1234000" (12 car.)
⚠️ Mesurer le bon morceau Le nombre de zéros = 12 - len(code), pas 12 - len(seat) : c'est le début complet (siège + vol) qu'on complète, pas juste le siège.
🤔 "1A" + "CO1234" fait 8 caractères. Combien de zéros pour arriver à 12 ?
4 (12 - 8) → "1ACO12340000".
